## 七、后续强制规则

以后每个需求批次必须形成以下闭环：

```text
需求条目
→ 允许修改文件/冻结行为
→ 基线 SHA
→ 失败回归测试
→ 最小实现
→ 全量测试/typecheck/build
→ Spec Reviewer
→ Quality Reviewer
→ 提交
→ 推送
→ Windows/真实场景验收
→ 版本记录
```

禁止：

- 多个独立需求混入一个提交；
- 只改代码不更新需求事实源；
- 只跑单元测试就宣称 WebView 修复；
- 审查未通过就提交或打包；
- 未记录主要修改内容就推送；
- 从旧代码行为反推用户需求。
