# 版本需求与回归门禁

## 核心原则

1. 已稳定功能默认冻结。当前任务未点名的业务逻辑、交互、窗口生命周期、重试策略不得修改。
2. 修复必须外科手术式：只改导致当前问题的最小代码路径。
3. 修改前工作区必须 clean，并记录当前基线 commit SHA；若有未提交内容先拆分提交或 stash，禁止为了制造基线而提交不明改动。修改后单独提交。
4. 禁止把多个需求、重构、优化、UI 调整和 bug 修复塞进同一提交。
5. 若必须触碰稳定路径，先列出受影响行为、回归测试和回滚点；未完成不得修改。

## 版本职责确认

每次改动前写清：

- 当前需求：本提交唯一要解决的问题。
- 允许修改的文件与函数。
- 明确不变的稳定行为。
- 验证命令与人工验收场景。

提交后检查：

```bash
git diff <baseline>..HEAD --stat
git diff <baseline>..HEAD -- <稳定路径文件>
```

若稳定路径出现非必要 diff，立即回滚，不解释为“顺便优化”。

## 豆包 WebView 冻结行为

以下行为属于已稳定契约，除非用户明确要求修改，否则禁止改变：

- 单段生成窗口从打开、提交到拿到视频 URL 期间保持运行；仅成功、明确失败、超时、用户取消时关闭。
- 提交失败不得自动切换账号；必须保留窗口供人工检查，并记录日志。
- 手工指定账号失败不得切换其他账号。
- 自动选号只有在明确的账号级错误（未登录、登录态过期、额度不足）时才能切换账号。
- 参数确认回复必须使用追加语义，不得复用会清空主提示词或图片状态的提交脚本。
- “打开豆包”必须使用生成时同一账号分区，并能看到该账号对应的会话历史。

## 强制测试 TODO

仓库目前没有覆盖真实 WebView 生命周期的自动测试。该事项为项目正式 TODO，未完成前不得声称 WebView 生成链路已具备自动回归保障。后续必须补：

1. 提示词成功提交后窗口不提前关闭。
2. 等待视频期间不会切换账号。
3. 提交失败保留窗口并返回明确错误。
4. 自动模式只对账号级错误换号。
5. 手工指定账号永不换号。
6. 确认消息使用追加脚本，不清空提示词、图片和上下文。
7. 只有拿到视频 URL、超时、明确失败或用户取消时销毁窗口。
8. 日志写入用户可见位置，并提供“打开日志”入口。

在这些测试补齐前，任何涉及 `webview-engine.ts`、`dispatch.ts` 账号重试、窗口关闭逻辑的改动，都必须进行人工场景验收并由独立 reviewer 审查。
