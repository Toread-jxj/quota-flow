# 批量注册用户脚本

> 日期：2026-11-09
> 脚本：`scripts/register_users.py`
> 适用场景：本地自托管 Supabase（无 SMTP 邮件服务），跳过邮件验证直接创建账号

## 1. 背景

自托管 Supabase 默认未配置 SMTP，正常 signup 流程发的确认邮件收不到，用户无法激活账号。为批量开通账号，脚本直接向 `auth.users` INSERT 一行，依赖触发器 `on_auth_user_created` 自动建 `profiles`，并跳过邮件验证（`email_confirmed_at` 置为 `now()`）。

## 2. 用法

```bash
# 逐个邮箱
python3 scripts/register_users.py a@x.com b@x.com

# 从文件/管道读取（每行一个邮箱）
echo -e "a@x.com\nb@x.com" | python3 scripts/register_users.py -
```

脚本会：

- 生成 6 位易读随机密码（去掉 0/O/1/l/I 等易混淆字符）
- 去重（已存在的邮箱跳过）
- 打印「邮箱 / 密码 / 状态」结果表

## 3. 关键坑：auth.users 直插字段必须非 NULL

**症状**：登录时报 `Database error querying schema`，Auth 日志出现：

```
Scan error on column index 3, name "confirmation_token": converting NULL to string is unsupported
```

**根因**：GoTrue 查询用户时用 Go 的 `string`（非 `sql.NullString`）扫描以下列，值为 NULL 时直接崩溃（HTTP 500）。这些列必须显式给空串 `''`：

| 列 | 正确值 |
|----|--------|
| `confirmation_token` | `''` |
| `recovery_token` | `''` |
| `email_change_token_new` | `''` |
| `email_change` | `''` |
| `email_change_token_current` | `''` |
| `phone_change` | `''` |
| `phone_change_token` | `''` |
| `reauthentication_token` | `''` |
| `raw_app_meta_data` | `{"provider":"email","providers":["email"]}` |
| `raw_user_meta_data` | 含 `sub`（= id）、`email`、`email_verified:true` |

> 注意：`phone` 为 NULL 是**正常**的（GoTrue 用 `NullString` 扫描，未绑手机号即为 NULL），不要误当 bug 去填。

其中 `raw_user_meta_data.sub` 必须与 `id` 一致（标准注册时 `sub` = `id`），否则客户端 `getUser()` 解析出的用户身份对不上。

## 4. 修复记录

- 2026-11-09：脚本初版漏设 `confirmation_token` 等字段（INSERT 时这些列落入 NULL），导致登录崩溃。已修复为显式空串 + 标准 `raw_app_meta_data` / `raw_user_meta_data`。历史已注册账号同步 UPDATE 补齐字段。

## 5. 验证

登录成功后，`profiles` 表应自动出现对应 `id` 的行（触发器 `on_auth_user_created` 自动建）。

```sql
SELECT email, confirmation_token, raw_app_meta_data, raw_user_meta_data
FROM auth.users WHERE email = '<邮箱>';
-- 预期：confirmation_token 为 ''，raw_user_meta_data.sub 等于该行 id
```
